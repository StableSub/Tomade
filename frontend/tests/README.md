# 사무실 UI 브라우저 회귀 검사

Vite를 실행한 상태에서 Node와 설치된 Playwright로 실행합니다. 모든 `/api/**` 요청은 테스트의 메모리 데이터와 제어 가능한 SSE 스트림으로 가로채므로 실제 대화 DB·Toss·LLM을 호출하지 않습니다.

```sh
# 프로젝트에서 playwright를 해석할 수 있는 환경
node frontend/tests/office-ui.mjs

# 다른 위치에 설치된 Playwright와 기존 Chrome 사용
PLAYWRIGHT_MODULE_PATH=/absolute/path/to/node_modules/playwright \
OFFICE_BROWSER_CHANNEL=chrome \
node frontend/tests/office-ui.mjs
```

`OFFICE_BASE_URL` 기본값은 `http://127.0.0.1:5173`입니다. `OFFICE_SCREENSHOTS_DIR` 기본값은 `/tmp/stock-office-ui-test`입니다. 브라우저가 없으면 Playwright 브라우저를 준비하거나 설치된 Chrome 채널을 지정해야 합니다.

독립 소품 검사는 49개 에셋 ID를 131개 오브젝트로 로딩하는지, 이전 배경 PNG를 요청하지 않는지, 명패·상단 메뉴 제거, 캐릭터 클릭과 다섯 캐릭터의 미니맵 inert 상태를 확인합니다. 실제 바닥 Canvas의 픽셀을 읽어 직원 공간의 완전한 9×6 블록·블록당 3개 판재·1픽셀 이음선과 부장실의 6×6 평면 체크를 검증합니다. 벽 걸레받이에서 시작하는 바닥, 목재 통로·문턱·계단·기단의 연결 및 입구 끝단도 확인합니다. `modular-office.png`에 조립된 사무실을 저장합니다.

입구·통로 바닥이 기둥 안쪽에서 끝나는지, 계단이 입구 바닥에 연결되는지, 가운데 칸막이와 기둥의 좌우 경계가 일치하는지도 확인합니다. 앞쪽 벽지 두 면을 제거한 뒤에도 뒤쪽 벽지 두 면은 유지합니다.

색상 검사는 윤곽선을 제외한 내부 픽셀을 원본 PNG·아틀라스 프레임의 투영과 직접 비교해 RGB가 바뀌지 않았는지 확인합니다. 승인된 직원 책상은 세 자리에서 같은 원본을 사용하며, 소품·마당·프레임·체크 바닥 모두 원본 색상 보존 대상입니다. 공통 팔레트로 색상 수를 제한하는 검사는 사용하지 않습니다.

소품 렌더링 검사는 실제 직원 캐릭터와 같은 0.54게임단위 픽셀 배율, 66개 오브젝트의 실루엣 안쪽 2픽셀 검정 윤곽, 원본 투영 대비 알파·구멍 보존, 0/255 투명도를 확인합니다. 바닥·평평한 벽면·작은 풀과 들꽃에는 추가 윤곽을 요구하지 않습니다. DPR 1·2와 데스크톱·모바일 크기에서 128개 비타일 Canvas가 실제 기기 픽셀 크기에 맞는지, 직원 책상의 직선 테두리가 끊기지 않는지, 부장 모니터가 중앙에 있고 받침대가 상판 안에 있는지 확인합니다. 두 뷰어의 50개 상세 창도 모두 열어 빈 그림·스크립트 오류를 검사합니다. `sprite-office-dpr*.png`, `sprite-desk-dpr*.png`, `office-*-v1-rendering.png`는 육안 검토용 캡처입니다. 원본 그림 자체의 모든 선 굵기를 수학적으로 동일하게 만드는 검사는 아닙니다.

걷기 검사는 실제 RAF에서 네 방향·4프레임 전신 그림, 가로로 긴 방의 이동 거리와 걸음의 일치, 출발 가속, 정지 자세, 모션 설정 전환을 확인합니다. 화면 크기별 캐릭터 비율·클릭 영역과 착석도 확인합니다. `walking-frames.html`에는 실제 Canvas에서 캡처한 걷기 프레임을 모아 육안 검토할 수 있게 저장합니다.

두 방 검사는 부장과 직원의 산책 영역 분리, 네 작업 자리의 착석, 모든 직원이 가운데 문으로만 이동해 부장실에 보고하는지, 완료 후 부장 대화 진입을 확인합니다. `two-room-working.png`, `two-room-reporting.png`, `two-room-manager-arrived.png`에서 실제 배치를 확인할 수 있습니다.

대화 집중 모드에서는 같은 사무실 DOM의 중간 축소 프레임, 미니맵 복귀·키보드 접근, 작성 중 입력 유지, 모든 사용자 말풍선의 오른쪽 정렬, 여러 턴의 스트리밍·복원·중복 없음, 읽던 스크롤 위치 유지, 모바일·가로 화면과 모션 감소를 확인합니다. `focus-chat-<폭>x<높이>.png`에 각 화면의 결과를 저장합니다.

확인 범위: 데스크톱·세로 창·모바일·가로 화면에서 사무실 전체 맞춤과 스크롤 없음, 실제 RAF 산책, 새 책상 좌표의 선택 Worker 착석, 진행률·스트리밍 보고서, 최종 답변 시 부장 대화창, 오류·연결 종료 시 모션 정리, 대화 생성·전환·삭제·복원·pending 재조회, 포트폴리오 지연 로딩, 모바일 긴 답변·노트, 모션 감소, 완료 시 열린 보조 창 처리. bfcache 관련 검증은 합성한 persisted pagehide/pageshow 이벤트 수준이며 실제 브라우저 뒤로 가기 캐시 복원은 별도 확인 대상입니다.

입구 v2 검사는 별도 끝단·문턱·계단이 중복 배치되지 않는지, 입구 상단이 비어 있는지, 목재 문턱과 두 석재 계단이 존재하는지, 양옆 기단 아래에 계단 픽셀 조각이 반복되지 않는지를 실제 Canvas로 확인합니다.

프레임 접합 검사에서는 전면의 네 아틀라스 절단 위치에서 상단 알파·밝은 목재 면·좌우 색 연결을 검사하고, 처마가 하나의 연속 오브젝트인지 확인합니다. 가구·마당 원본 RGB 보존 검사와 별개로 집 프레임 목재는 사용자가 지정한 입구 색에 맞춰 보정합니다.

부장 대화창·커비 포트폴리오 검사는 부장 대화창 내부 기록 선택·생성·삭제, 질문 오른쪽 정렬, 이동하는 이름의 위치 동기화, 커비의 분홍색 보존·청록 키 제거·지연 로딩, 데스크톱/390px 모바일 배치, 고정 헤더와 표 스크롤을 확인합니다. 포트폴리오는 모의 계좌 결과·미설정·오류 상태를 검사하며 재열기 시 진단이 다시 실행되지 않아야 합니다. 실제 계좌·LLM은 호출하지 않습니다. `history-modern-*.png`, `portfolio-modern-*.png`가 시각 검토 결과입니다.

커비 검사는 96×96 기준 격자와 직원과 동일한 크기 비율, Canvas와 실제 표시 기기 픽셀의 일치, 줄어든 표시 크기, 실제 RAF 이동에서 네 방향 × 네 개의 서로 다른 발 자세, 가구를 피하는 동선, 정지·키보드 포커스·포트폴리오 열기·모션 감소·페이지 숨김/복귀 동작을 확인합니다. 걷기만으로 API를 호출하지 않으며 포트폴리오는 모의 API로만 엽니다. `kirby-small-office-dpr*.png`와 `kirby-walking-frames-dpr*.png`를 함께 육안 검토합니다.

커비 테두리는 실제 표시 Canvas에서 네 방향 × 네 걸음의 모든 알파 경계에 어두운 윤곽이 연속되는지 검사합니다. 매트 원본 Canvas의 평평한 외곽에서 기본 두께를 측정하고, 화면 배율로 환산한 값과 커비 각 자세의 상단·하단·좌우 선 두께의 최빈값을 비교합니다. 단순히 윤곽이 끊기지 않는지만 통과시키지 않습니다. 기본 검사에서 일반 배율과 Retina 배율을 모두 실행합니다. 원본 에셋 파일의 변경은 필요하지 않습니다.

## 풍경·그림자 집중 검사

Vite 실행 후 `/tests/office-environment.html`을 브라우저로 열면 28개 확인 항목의 PASS/FAIL과 창문 전후 비교, 390px 모바일 사무실을 표시합니다. 실제 Canvas에서 희미한 알파 여백의 잘라내기, 창문 풍경 변경·기존 알파와 창틀 보존, 두 크기 그림자의 공통 픽셀 격자·0/255 알파·캐시를 검사합니다. 실제 `OfficeRoom`과 CSS를 1440×1000·844×390·390×844 iframe에 마운트해 131개 오브젝트의 잘림과 대화 모드의 마당 숨김과 13개 신규 소품 배치가 집 안을 침범하거나 클릭을 가로채지 않는지 검증합니다. `app.ts`를 실행하지 않으므로 실제 계정·대화·LLM API는 호출하지 않습니다. 전체 앱의 스트리밍·포트폴리오 회귀 검사를 대체하지 않습니다.
